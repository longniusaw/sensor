# MicoAir743v2 PX4 通过 UART + Micro XRCE-DDS 接入 ROS 2 Jazzy

总结：
1.先连线，连接c340串口转ttl以及typec，然后接到电脑上
2.透传，透传c340到wsl里
3.启动wsl端的dds  MicroXRCEAgent serial --dev /dev/ttyUSB0 -b 921600
4.检查qgc的连接情况，同时启动qgc也就是px4飞控板端的dds  uxrce_dds_client start -t serial -d /dev/ttyS0 -b 921600
5.注意飞控端的ros id

## 1. 项目目标

本次工作旨在将真实的 MicoAir743v2 飞控接入 ROS 2 Jazzy，使 ROS 2 节点能够订阅 PX4 发布的飞行器状态数据，并为后续的飞控状态监控、传感器融合、Offboard 控制和算法平台集成提供基础。

最终实现以下通信链路：

```text
                 Windows
              ┌────────────┐
              │    QGC     │
              │            │
              └─────┬──────┘
                    │ USB-C
                    │ MAVLink
                    ▼
              ┌────────────┐
              │ MicoAir    │
              │ 743v2 PX4  │
              │            │
              │ PX4 Client │
              └─────┬──────┘
                    │ UART1
                    │ 921600 baud
                    ▼
              ┌────────────┐
              │  CH340G    │
              └─────┬──────┘
                    │ USB
                    ▼
              ┌────────────┐
              │    WSL2    │
              │            │
              │ XRCE-DDS   │
              │   Agent    │
              └─────┬──────┘
                    │ DDS
                    ▼
              ┌────────────┐
              │ ROS 2      │
              │ Jazzy      │
              │            │
              │ Domain 10  │
              └────────────┘
```

核心目标：

1. 建立 PX4 与 Micro XRCE-DDS Agent 之间的串口通信。
2. 通过 Agent 将 PX4 的 uORB 消息转换为 ROS 2 可发现的 DDS 话题。
3. 在 ROS 2 Jazzy 中发现 `/fmu/out/*` 和 `/fmu/in/*` 话题。
4. 成功订阅真实飞控数据，验证数据发布频率和消息内容。
5. 为后续编写 ROS 2 C++ 飞控状态监控节点打好基础。

## 3. 硬件接线

本次使用 CH340G USB 转 TTL 串口模块连接飞控 UART1。

### 3.1 接线关系

| CH340G | MicoAir743v2 |
|---|---|
| TXD | UART1 RX1 |
| RXD | UART1 TX1 |
| GND | GND |
| VCC | 不连接 |

注意：

- TX 和 RX 需要交叉连接。
- 两端必须共地。
- CH340G 使用 3.3V TTL 逻辑电平。
- 不要将 CH340G 的 VCC 接到飞控供电端。
- 飞控通过 USB-C 或独立电源供电。
- 连接前确认 UART1 的引脚定义和电平规格。

### 3.2 为什么使用 UART，而不是直接使用飞控 USB-C？

本次保留两条独立链路：

**链路一：飞控调试**

```text
Windows QGC
    |
  USB-C
    |
  PX4
```

用于：

- MAVLink Console。
- 查看 PX4 参数。
- 启动和停止 DDS Client。
- 查看飞控状态和调试信息。

**链路二：ROS 2 数据通信**

```text
PX4 UART1
    |
  CH340G
    |
  WSL2
    |
Micro XRCE-DDS Agent
    |
  ROS 2
```

用于：

- 传输 PX4 DDS 消息。
- 订阅飞控状态。
- 后续发送 ROS 2 控制指令。

这种方式避免了将飞控 USB-C 设备从 Windows 转交给 WSL，同时保留 QGC 的调试能力。

## 4. Windows 与 WSL2 串口设备配置

Windows 默认识别 CH340G 为 COM 串口设备，需要通过 usbipd 将其转交给 WSL2。

### 4.1 检查 USB 设备

在 Windows 管理员 PowerShell 中执行：

```powershell
usbipd list
```

找到 CH340G 设备，实际识别信息：

```text
USB-SERIAL CH340
VID:PID = 1a86:7523
```

本次设备曾被识别为 COM15。

注意：COM 编号可能随着设备重新连接而变化。

### 4.2 共享 USB 设备

假设 CH340G 对应的 BUSID 为 `5-1`：

```powershell
usbipd bind --force --busid 5-1
```

然后将设备附加到 WSL：

```powershell
usbipd attach --wsl --busid 5-1
```

参数说明：

- `bind`：将 USB 设备设置为可共享。
- `--force`：强制执行共享操作。
- `attach --wsl`：将设备附加到 WSL 环境。
- `--busid`：指定 USB 设备的总线编号。

BUSID 以实际 `usbipd list` 输出为准，不要直接照抄示例编号。

### 4.3 在 WSL 中检查设备

进入 Ubuntu：

```bash
lsusb
```

正常情况下应能看到类似设备：

```text
QinHeng Electronics CH340 serial converter
```

查看串口设备：

```bash
ls -l /dev/ttyUSB*
```

本次成功识别：

```text
/dev/ttyUSB0
```

### 4.4 加载 CH340 驱动

如果没有自动生成 `/dev/ttyUSB0`，可以尝试：

```bash
sudo modprobe ch341
```

检查：

```bash
ls -l /dev/ttyUSB0
```

Linux 内核通过 `ch341` 驱动支持 CH340 系列 USB 转串口芯片。

### 4.5 串口访问权限

本次设备权限最初为：

```text
crw------- 1 root root ... /dev/ttyUSB0
```

为了验证通信，曾使用：

```bash
sudo chmod 666 /dev/ttyUSB0
```

这会允许当前系统中的所有用户读写该设备，仅建议作为临时调试手段。

更适合长期使用的方式是将用户加入 `dialout` 组：

```bash
sudo usermod -aG dialout $USER
```

之后注销并重新登录 WSL，使用户组变更生效。

检查：

```bash
groups
```

确认输出中包含 `dialout`。

### 4.6 检查串口是否被占用

```bash
sudo fuser -v /dev/ttyUSB0
```

如果没有输出，通常表示当前没有进程占用该串口。

注意：串口只能由一个 Agent 进程正常独占使用，不要同时启动多个 Agent 争用 `/dev/ttyUSB0`。

## 5. PX4 UART1 与 uXRCE-DDS 配置

### 5.1 确认 UART1 设备映射

本次 MicoAir743v2 固件中，PX4 UART1 对应：

```text
/dev/ttyS0
```

这是本次成功启动 DDS Client 所使用的设备路径。

不要将 Linux 侧的 `/dev/ttyUSB0` 和 PX4 侧的 `/dev/ttyS0` 混淆：

| 设备路径 | 所属环境 | 含义 |
|---|---|---|
| `/dev/ttyUSB0` | WSL Ubuntu | CH340G USB 串口设备 |
| `/dev/ttyS0` | PX4 NuttX | 飞控 UART1 |

### 5.2 检查 DDS 配置参数

通过 QGC 的 MAVLink Console 执行：

```sh
param show UXRCE_DDS_CFG
```

本次读取到：

```text
UXRCE_DDS_CFG : 100
```

该参数在当前厂商固件中的具体含义尚未完全确认，因此不对其进行修改。

继续检查 DDS Domain ID：

```sh
param show UXRCE_DDS_DOM_ID
```

最初读到：

```text
UXRCE_DDS_DOM_ID : 0
```

为了与现有 ROS 2 项目统一，将其修改为 10：

```sh
param set UXRCE_DDS_DOM_ID 10
```

再次检查：

```sh
param show UXRCE_DDS_DOM_ID
```

期望结果：

```text
UXRCE_DDS_DOM_ID : 10
```

保存参数：

```sh
param save
```

说明：保存操作用于让参数配置在飞控重启后继续保留。

### 5.3 启动 PX4 uXRCE-DDS Client

在 QGC MAVLink Console 执行：

```sh
uxrce_dds_client start -t serial -d /dev/ttyS0 -b 921600
```

参数解释：

| 参数 | 含义 |
|---|---|
| `start` | 启动 DDS Client |
| `-t serial` | 使用串口传输 |
| `-d /dev/ttyS0` | 指定 PX4 UART1 |
| `-b 921600` | 设置串口波特率 |

成功时会看到类似输出：

```text
INFO [uxrce_dds_client] init serial /dev/ttyS0 @ 921600 baud
INFO [uxrce_dds_client] synchronized with time offset ...
INFO [uxrce_dds_client] successfully created rt/fmu/out/battery_status data writer
INFO [uxrce_dds_client] successfully created rt/fmu/out/vehicle_attitude data writer
INFO [uxrce_dds_client] successfully created rt/fmu/out/vehicle_status data writer
INFO [uxrce_dds_client] time sync converged
```

其中：

- `init serial`：串口初始化成功。
- `synchronized with time offset`：建立时间同步。
- `successfully created ... data writer`：成功创建对应 DDS 发布实体。
- `time sync converged`：时间同步收敛。

注意：创建 DataWriter 表示 DDS 实体创建成功，但还不能单独证明 ROS 2 已经发现话题并接收到消息。还需要在 ROS 2 侧验证。

### 5.4 检查 Client 状态

```sh
uxrce_dds_client status
```

如果正在运行，应显示相应的运行状态。

停止 Client：

```sh
uxrce_dds_client stop
```

## 6. 启动 Micro XRCE-DDS Agent

### 6.1 Agent 的作用

PX4 本身并不直接通过普通 ROS 2 节点发布话题。

它使用 uXRCE-DDS Client，通过串口将数据传输给 Micro XRCE-DDS Agent。

Agent 负责将 Client 的 DDS 实体映射到 ROS 2 所使用的 DDS 网络中。

整体关系：

```text
PX4 uORB
   |
   ▼
uXRCE-DDS Client
   |
   ▼
UART Serial
   |
   ▼
Micro XRCE-DDS Agent
   |
   ▼
DDS Middleware
   |
   ▼
ROS 2 Jazzy
```

### 6.2 启动串口 Agent

在 WSL 中打开一个独立终端，执行：

```bash
MicroXRCEAgent serial --dev /dev/ttyUSB0 -b 921600
```

参数解释：

| 参数 | 含义 |
|---|---|
| `serial` | 使用串口传输模式 |
| `--dev` | 指定串口设备 |
| `/dev/ttyUSB0` | WSL 中的 CH340G |
| `-b 921600` | 串口波特率 |

Agent 启动后应保持该终端运行，不要关闭。

### 6.3 启动顺序

推荐按照以下顺序：

1. 连接飞控和 CH340G。
2. 在 Windows 中将 CH340G 附加到 WSL。
3. 在 WSL 中确认 `/dev/ttyUSB0` 存在。
4. 启动 Micro XRCE-DDS Agent。
5. 在 QGC 中启动 PX4 uXRCE-DDS Client。
6. 在另一个 WSL 终端中检查 ROS 2 话题。

注意：不要同时运行之前使用的 UDP Agent 和当前串口 Agent，以免干扰排查。

## 7. ROS 2 Jazzy 环境配置

### 7.1 加载 ROS 2 环境

在 WSL 新终端执行：

```bash
source /opt/ros/jazzy/setup.bash
```

### 7.2 设置 DDS Domain ID

PX4 当前参数为：

```text
UXRCE_DDS_DOM_ID = 10
```

因此 ROS 2 侧也设置为：

```bash
export ROS_DOMAIN_ID=10
```

检查：

```bash
echo $ROS_DOMAIN_ID
```

期望：

```text
10
```

DDS Domain ID 用于区分不同的 DDS 通信域。

只有处于相同通信域、且网络发现条件满足的参与者，才能正常发现彼此。

本项目统一使用 Domain ID 10，避免与其他默认 Domain ID 0 的 ROS 2 测试环境混淆。

### 7.3 检查 ROS 2 环境

```bash
printenv | grep -E 'ROS_DOMAIN_ID|RMW_IMPLEMENTATION|ROS_LOCALHOST_ONLY'
```

其中：

- `ROS_DOMAIN_ID`：ROS 2 通信域。
- `RMW_IMPLEMENTATION`：ROS 2 使用的中间件实现。
- `ROS_LOCALHOST_ONLY`：是否限制本机通信。

本次最终成功的关键配置是 PX4 和 ROS 2 使用相同的 Domain ID 10。

如果后续出现发现异常，再进一步检查 RMW 实现和网络配置。

### 7.4 清理 ROS 2 Discovery Daemon

修改 Domain ID 后，建议执行：

```bash
ros2 daemon stop
```

然后重新检查：

```bash
ros2 topic list
```

如果需要直接查询而不使用 ROS 2 CLI Daemon：

```bash
ros2 topic list --no-daemon
```

## 9. 本次遇到的问题与解决过程

### 问题一：PX4 Client 能启动，但 ROS 2 看不到话题

最初 PX4 执行：

```sh
uxrce_dds_client start -t serial -d /dev/ttyS0 -b 921600
```

可以看到：

```text
successfully created rt/fmu/out/vehicle_attitude data writer
time sync converged
```

但 ROS 2 只看到：

```text
/parameter_events
/rosout
```

说明 PX4 Client 与 Agent 已经完成了部分通信初始化，但 ROS 2 侧尚未发现 PX4 话题。

排查过程中检查了：

```sh
param show UXRCE_DDS_DOM_ID
```

发现 PX4 的 Domain ID 原本为 0。

为了与 ROS 2 开发环境统一，修改为：

```sh
param set UXRCE_DDS_DOM_ID 10
```

并在 ROS 2 侧使用：

```bash
export ROS_DOMAIN_ID=10
```

随后停止并重新启动 PX4 Client。

最终成功发现 `/fmu/in/*` 和 `/fmu/out/*` 话题。

### 问题二：修改参数后需要重新启动 PX4 DDS Client

本次最终成功的操作流程：

```sh
uxrce_dds_client stop
```

检查：

```sh
uxrce_dds_client status
```

确认停止后重新启动：

```sh
uxrce_dds_client start -t serial -d /dev/ttyS0 -b 921600
```

随后 ROS 2 成功发现话题。

这次实践说明：修改 DDS Domain ID 后，应重新启动 PX4 DDS Client，使新的配置应用于通信会话。

### 问题三：Windows 与 WSL 串口设备容易混淆

本次同时使用了两个 USB 通信接口：

- 飞控 USB-C：保留给 Windows QGC。
- CH340G：转交给 WSL，负责 DDS 串口通信。

如果不注意 usbipd 的设备绑定和附加状态，可能导致设备被错误地交给 WSL，或者 Windows 无法正常访问 QGC 串口。

因此后续维护时需要明确区分两个设备。

## 10. 日常启动流程（快速复现）

以下是整个项目成功后建议使用的启动顺序。

```powershell
usbipd list
```

```bash
source /opt/ros/jazzy/setup.bash

ls -l /dev/ttyUSB0
```

保持终端运行。

```sh
param show UXRCE_DDS_DOM_ID
uxrce_dds_client status
```

确认 Domain ID 为 10，且 Client 未运行时执行：

```sh
uxrce_dds_client start -t serial -d /dev/ttyS0 -b 921600
```

```bash
source /opt/ros/jazzy/setup.bash
export ROS_DOMAIN_ID=10
```

```bash
ros2 topic hz /fmu/out/vehicle_attitude
```

读取状态：

```bash
ros2 topic echo /fmu/out/vehicle_status --once
```

## 11. 后续开发计划

目前已经完成真实 PX4 飞控到 ROS 2 的基础数据接入，下一步应从通信验证转向 ROS 2 应用开发。

### 阶段一：PX4 状态监控节点

创建一个 C++ ROS 2 Package，例如：

```text
px4_state_monitor/
├── CMakeLists.txt
├── package.xml
├── include/
│   └── px4_state_monitor/
└── src/
    └── px4_state_monitor_node.cpp
```

订阅：

```text
/fmu/out/vehicle_attitude
/fmu/out/vehicle_status
/fmu/out/vehicle_local_position
/fmu/out/battery_status
```

功能：

- 获取飞行器姿态。
- 获取飞行器解锁状态。
- 获取本地位置和速度。
- 获取电池状态。
- 定时输出整合后的飞控状态。

### 阶段二：数据处理与坐标转换

进一步学习：

- PX4 姿态四元数。
- 欧拉角与四元数转换。
- NED 与 ENU 坐标系转换。
- PX4 时间戳与 ROS 2 时间。
- `geometry_msgs` 与 PX4 消息类型的关系。
- TF2 坐标变换。

尤其要注意 PX4 常用 NED 坐标系与 ROS 常用 ENU 坐标系的区别，不能直接把坐标值照搬到 ROS 可视化中。

### 阶段三：Offboard 控制接口

在充分理解 PX4 Offboard 安全要求后，再考虑订阅 ROS 2 控制指令并发布：

```text
/fmu/in/offboard_control_mode
/fmu/in/trajectory_setpoint
/fmu/in/vehicle_command
```

重点学习：

- Offboard 心跳和设定值发布频率。
- 模式切换。
- 解锁与上锁。
- 位置控制与速度控制。
- 指令确认与超时处理。
- 安全退出和失联保护。

此阶段应先在仿真环境验证，再进行受控的实机测试。不要直接向未固定的真实飞行器发送解锁或运动指令。

### 阶段四：整合现有算法平台

将真实 PX4 数据接入此前的 ROS 2 算法平台：

```text
                ROS 2 Algorithm Platform
                         |
          ┌──────────────┼──────────────┐
          |              |              |
      Commanding     Arbitration   Communication
          |              |              |
          └──────────────┼──────────────┘
                         |
                    PX4 Adapter
                         |
                   /fmu/in/*
                         |
                       PX4
                         |
                   /fmu/out/*
                         |
                  State Feedback
```

目标是形成：

- ROS 2 统一命令入口。
- 指令仲裁。
- PX4 指令适配。
- 飞控状态反馈。
- 指令执行结果验证。

这将使之前的算法平台项目从仿真或接口层面的开发，进一步具备真实飞控数据接入能力。
