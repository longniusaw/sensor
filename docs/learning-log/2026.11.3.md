# 激光雷达与 TOF 测距模块联调技术日志

## 🌅 上午：ESP32-S3 连接 VL53L0X TOF 激光测距模块

**任务简述**：完成 TOF 红外激光测距模块与 ESP32-S3 的连接，实现电脑 USB 供电 -> ESP32 -> 模块的供电链路，并跑通测距程序。

### 1. 硬件准备
*   **主控板**：ESP32-S3 开发板（通过电脑 USB 供电）
*   **传感器**：VL53L0X TOF 激光测距模块（YAHBOOM 版，支持 3.3V/5V 供电）
*   **连接线**：杜邦线若干

### 2. 接线方案
**核心避坑点**：ESP32-S3 的默认 I2C 引脚（通常是 GPIO 8/9）与老款 ESP32 不同，且开发板引出引脚各异。本方案根据实际开发板丝印及测试，使用了 **GPIO 38 (SDA)** 和 **GPIO 37 (SCL)**。

| VL53L0X 模块引脚 | 接到 ESP32-S3 | 说明 |
| :--- | :--- | :--- |
| **VCC** | **5V** | 该模块板载稳压/电平转换，支持 5V 直接供电。 |
| **GND** | **GND** | 必须共地。 |
| **SDA** | **GPIO 38** | 数据线（对应板子上的 SDA 丝印）。 |
| **SCL** | **GPIO 37** | 时钟线（对应板子上的 SCL 丝印）。 |

> ⚠️ **注意**：接线前请确保 ESP32 处于断电状态，接好后再插 USB。

### 3. 软件环境与测试代码
*   **开发环境**：Arduino IDE (C++ 面向对象语法)
*   **依赖库**：`Adafruit VL53L0X`

```cpp
#include <Wire.h>
#include <Adafruit_VL53L0X.h>

Adafruit_VL53L0X lox = Adafruit_VL53L0X();

void setup() {
  Serial.begin(115200);
  while (!Serial) delay(1);
  
  Serial.println("VL53L0X 测试开始");
  
  // 【关键避坑】ESP32-S3 必须指定实际的 SDA 和 SCL 引脚
  Wire.begin(38, 37); 
  
  if (!lox.begin()) {
    Serial.println("初始化失败！请检查接线或供电");
    while (1); // 停在死循环
  }
  Serial.println("传感器就绪，开始测距...");
}

void loop() {
  VL53L0X_RangingMeasurementData_t measure;
  lox.rangingTest(&measure, false);
  
  if (measure.RangeStatus != 4) { // 状态 4 代表超出量程
    Serial.print("距离: ");
    Serial.print(measure.RangeMilliMeter);
    Serial.println(" mm");
  } else {
    Serial.println("超出量程");
  }
  delay(200);
}
```

### 4. 核心问题排查记录 (Troubleshooting)
*   **报错**：`fatal error: Adafruit_VL53L0X.h: No such file or directory`
    *   **原因**：未安装对应的驱动库。
    *   **解决**：IDE 中点击“工具” -> “管理库”，搜索并安装 `Adafruit VL53L0X`。
*   **串口打印“初始化失败”**：
    *   **原因**：ESP32-S3 默认 I2C 引脚不符，`Wire.begin();` 会尝试默认引脚（如 GPIO 8/9），导致找不到传感器。
    *   **解决**：明确指定引脚，改为 `Wire.begin(38, 37);`。

### 5. 使用建议
1.  **撕掉保护膜**：模块镜头如有出厂保护膜务必撕掉，否则激光折射会导致数据严重偏小或乱跳。
2.  **测距环境**：室内白墙反射好（可达 2 米）；强光或纯黑吸光材质会大幅缩短距离。
3.  **代码复用**：在 ESP32-S3 上使用 I2C 设备，必须确认引脚并主动在 `Wire.begin(SDA, SCL)` 中指定。

## 🌇 下午：ROS2 激光雷达驱动机制溯源与解析

**任务简述**：通过分析 `ydlidar_ros2_driver` 驱动源码，彻底搞懂了 2D 激光雷达从底层硬件到 ROS2 话题发布的完整数据流转链路。

### 1. 底层 SDK 解析（数据处理黑盒）
雷达通过串口（如 `/dev/ttyUSB0`）发出的其实是**十六进制的原始字节流**。
*   **SDK 的职责**：底层的 `YDLidar-SDK` 充当“翻译官”。它接收到原始数据后，会进行校验、剥离包头包尾，并根据雷达类型（三角测距或 TOF）利用算法计算出**极坐标数据**（角度 + 距离 + 强度）。
*   **输出结果**：SDK 不会直接发布 ROS 话题，而是将数据打包成底层 C++ 结构体，供上层调用。

### 2. ROS2 节点的数据搬运与计算（核心逻辑）
ROS2 驱动节点（如 `ydlidar_ros2_driver_node.cpp`）本质上是一个**数据的搬运工 + 翻译官**。
*   **数据拉取**：节点通过主循环，不断调用 SDK 提供的函数（如 `laser.doProcessSimple(scan)`），将底层算好的数据捞取到节点内存中。
*   **格式转换与计算**：
    *   **填充 LaserScan 消息**：按照 ROS2 标准，给 `sensor_msgs::msg::LaserScan` 填入时间戳、`frame_id`、最大/最小角度等参数。并通过计算当前角度所在的索引（`index`），将距离值精准填入 `ranges[]` 数组。
    *   **生成点云（极坐标 -> 直角坐标）**：在同一个循环中，利用三角函数 `X = 距离 * cos(角度)` 和 `Y = 距离 * sin(角度)`，将雷达的极坐标数据转换为了直角坐标系的 `PointCloud`（点云）数据。

### 3. 话题发布机制（ROS2 通信）
*   **发布者创建**：节点内部通过 `create_publisher` 创建发布者，将计算好的数据通过 `/scan` (LaserScan) 和 `/point_cloud` (PointCloud) 话题发布到网络中。
*   **命名空间避坑**：源码中的话题名通常**不带** `/`（直接写 `"scan"`），这是因为 ROS2 底层基于 DDS 通信，引入了相对命名空间机制。不带 `/` 代表相对名称，ROS2 会自动将其挂载到当前节点的命名空间下（默认根目录即变为 `/scan`）。这种写法极大地增加了驱动的通用性和灵活性（方便多雷达系统区分）。

### 💡 架构总结
从硬件到算法的链路为：**硬件物理测距 -> 串口字节流 -> 底层 SDK 解析 -> 驱动节点提取 -> 坐标转换/消息封装 -> ROS2 话题发布 -> 供上层导航算法使用。**
